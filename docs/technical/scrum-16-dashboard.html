Delivery-health dashboard + hidden-risk reveal

Ticket: SCRUM-16 · Owner: frontend · Status: current · Updated: 2026-07-30

1. Purpose

The Explain-adjacent surface of the Detect→Explain→Act→Govern→Report loop: for whichever project the tenant has selected, the delivery-health dashboard renders the sprint's "green surface" (health banner, four metric cards, story-point burndown, issue-status breakdown) and, in the same view, the hidden-risk reveal — the red attention banner and at-risk card for the story the board doesn't flag. Clicking "View evidence" opens a focus-trapped drawer citing the Detect engine's own reasons and evidence pointers. Both truths (surface health and hidden risk) are visible at once, sourced entirely from the live Detect API for the tenant's own connected project — never a hardcoded or demo dataset.

3. Design summary

Single-route SPA (no router — MVP scope is one dashboard screen, ARCHITECTURE.md §11). main.tsx wraps App in a QueryClientProvider. All server state goes through TanStack Query (src/api/queries.ts) — no fetching in render, no client-side scoring or business logic; the UI renders exactly what the backend returns.

No demo/hardcoded project (scope-change 2026-07-30). The dashboard no longer reads a build-time VITE_PROJECT_ID/VITE_SPRINT_ID or shows a static "Demo data" badge. App.tsx now calls the real useProjects() (GET /projects) and drives everything from that response:

  • Zero projects → NoProjectsEmptyState, a first-run page (not an afterthought) explaining there's nothing connected yet, with the ConnectProjectDialog CTA.
  • One or more projects → the top bar's ProjectSelector (a native, fully keyboard/screen-reader-accessible <select> — no new dependency) lists them by name/key; the first is auto-selected.
  • Selected project has a computed sprint snapshot (Project.latest_health, ARCHITECTURE.md §5.7 ProjectHealthSnapshot) → DashboardPage renders for that project.id + latest_health.sprint_external_id. Neither id is ever typed in or defaulted client-side — both come straight off the GET /projects response.
  • Selected project has no snapshot yet → an honest inline message, not a blank dashboard.

Multi-tenancy (cross-check docs/technical/multi-tenancy-and-project-grain.html). Tenant scoping is a server-side invariant (JWT org_id → Postgres RLS, ADR-006) — the frontend never sends or accepts an org id. Every project/sprint id the UI uses is sourced from a response the backend already scoped to the caller's tenant (GET /projects); a cross-tenant id typed into a URL would 404, never leak a row. This is why the project selector — not a free-text/URL id — is the only way to change which project's data is shown.

Data flow (dashboard, once a project+sprint are known): useSprintHealth(projectId, sprintId) calls GET /projects/{id}/sprints/{sprint_id}/health; useRiskReveal(projectId) calls GET /projects/{id}/risks and, because the loop runner (SCRUM-18) that would normally sequence Ingest→Detect doesn't exist yet, self-heals once — the first time the risk list comes back empty it fires POST /projects/{id}/risks/detect and refetches. This does not invent data client-side; it only asks the backend's own detector to run.

The reveal pattern (ux-spec §4.2): SprintHealthPanel and RiskReveal render in the same scroll region, both driven by their own StateBoundary (loading/error/success — never a blank screen). Nothing swaps out; the green surface stays visible while the risk card appears alongside it, which is the SCRUM-16 AC "contradiction visible in one view."

Modern, token-driven design system with real light/dark (scope-change 2026-07-30). Every semantic color name in tailwind.config.ts (canvas, surface, subtle, border, accent, text-*, status-*) resolves to a CSS custom property defined in src/index.css — a light value set under :root and a dark value set under @media (prefers-color-scheme: dark), following the shadcn rgb(var(--x) / <alpha-value>) convention. No component hardcodes a hex value or a raw Tailwind gray (the earlier border-slate-200-style classes were swapped for the border token; the burndown chart's inline SVG strokes read var(--chart-*) since Tailwind utilities don't reach raw stroke="" attributes). One accent (indigo) is used for primary actions and focus rings; risk semantics stay to green/amber/red. Cards dropped their drop-shadow in favor of a single subtle border (Linear/Vercel-style flat surface, not a legacy admin-panel shadow stack). All motion still respects prefers-reduced-motion (unchanged from the original build).

Accessibility fixes applied from docs/ux/ux-spec.md (§4.3, §9, §12 severity-ranked items) — unchanged by the scope-change pivot, still all in place:

  • [Blocker] Reveal announced to assistive tech — RiskReveal's outer <section> carries role="status" aria-live="polite" (WCAG 4.1.3).
  • [Blocker] Status not by color alone — status banners, badges, and the burndown chart all pair an icon/line-style + text label, and the burndown series is also exposed as a real, visually-hidden <table> (WCAG 1.4.1 / 1.3.1).
  • [High] Contrast — corrected light-mode values from the ux-spec carry over unchanged; dark-mode values follow the same Tailwind slate/semantic scale one step shifted, flagged here for a UX re-verify pass the same way the original light-mode fixes were called out one value at a time (§9 below).
  • [High] Explanation drawer is a focus-trapped, escapable dialog — Radix Dialog (WCAG 2.1.2); reused unmodified for ConnectProjectDialog.
  • [Medium] ≥24px targets — Button, the native ProjectSelector <select>, and evidence chips all keep a ≥36px hit area (WCAG 2.5.8).
  • Keyboard/focus order (§4.4) — SkipLink first, top-bar project selector → connect CTA → page content, visible :focus-visible ring (now accent-colored, still ≥3:1) global in index.css.

No new ADR required — this consumes the already-designed §5.6 endpoints as-is; no new runtime dependency was added (the project selector is a native <select>, not a new Radix/combobox package).

Manual walkthrough (ux-spec §11 Validate protocol, updated for the project-selector flow): load the app → with zero connected projects, the first-run empty state and its "Connect a project" CTA render (never a dashboard, never sample data) → once at least one project is connected and has a computed sprint snapshot, the dashboard for the first project loads automatically → the green "On track" surface renders → the red "Delivery Intelligence found N hidden risks" banner and card(s) appear in the same view → "View evidence" opens the focus-trapped drawer with the cited reasons/evidence rows → Esc returns focus to the trigger → switching projects via the top-bar selector re-fetches health/risks scoped to the newly selected project only. All from live GET calls, no client-side mocking.
